# KaiTOR Stability

Экспериментальный stability/diagnostics patch для The Old Realms на Mount & Blade II: Bannerlord 1.3.15.110062.

Цели v0.1:

- не изменять и не заменять TOR_Core.dll;
- сделать долгий запуск TOR понятным: отдельный монитор показывает реальный процесс Bannerlord, фазу загрузки, CPU/RAM, прошедшее время и ETA после калибровки;
- уменьшить стоимость `StatusEffectMissionLogic.OnMissionTick` в больших боях;
- оставить быстрый откат: оптимизация отключается одной настройкой;
- писать отдельный диагностический лог в `%LOCALAPPDATA%\KaiTORStability\KaiTORStability.log`.

## Как устроена оптимизация боя

Оригинальный TOR каждый кадр проходит по `Mission.Current.AllAgents`, хотя `StatusEffectComponent` внутри выполняет основную status-effect работу примерно раз в секунду. KaiTOR Stability заменяет только `StatusEffectMissionLogic` на совместимую реализацию:

- активные status components продолжают получать `OnTick(dt)` каждый кадр;
- полный поиск новых активных компонентов выполняется по умолчанию раз в 100 мс, а не каждый кадр;
- создание компонентов, mount sync и назначение постоянных карьерных эффектов сохраняются;
- при несовместимой версии TOR replacement не ставится и игра продолжает использовать оригинальную TOR logic.

100 мс — консервативное значение. При 60 FPS это уменьшает число полных проходов по армии примерно с 60 до 10 в секунду; при 120 FPS — примерно со 120 до 10. Активные эффекты при этом по-прежнему обновляются каждый кадр. Новому эффекту может потребоваться до `FullRescanIntervalMs` для попадания в активный набор.

## Монитор загрузки

`KaiTORLoadMonitor.exe` запускается до игры. Он запускает обычный TaleWorlds launcher и остаётся отдельным отзывчивым окном, поэтому продолжает показывать состояние даже когда окно Bannerlord помечено Windows как «Не отвечает».

Фазы v0.1:

1. поиск установки Bannerlord;
2. запуск TaleWorlds launcher;
3. обнаружение процесса Bannerlord;
4. загрузка TOR/модулей;
5. загрузка KaiTOR Stability после TOR_Core;
6. готовность начального экрана.

ETA намеренно не выдумывается на первом запуске. После первого успешного запуска сохраняется история времени; следующие ETA используют медиану последних пяти успешных запусков. Во время долгой фазы до загрузки модуля монитор отдельно объясняет, что игра может компилировать/готовить ресурсы и выглядеть зависшей.

## Порядок модулей

`KaiTOR_Stability` зависит от `TOR_Core`, поэтому должен грузиться после TOR:

`TOR_Armory -> TOR_Environment -> TOR_Core -> KaiTOR_Stability`

## Настройки

`Modules/KaiTOR_Stability/ModuleData/KaiTORStability.config.xml`

```xml
<KaiTORStability>
  <BattleStatusOptimization enabled="true" fullRescanIntervalMs="100" />
</KaiTORStability>
```

Для мгновенного отката без удаления мода поставьте `enabled="false"`.

## Статус

v0.1 — экспериментальная сборка. Сначала проверяем запуск, обычный бой и большой бой на одном и том же сохранении. Баланс TOR намеренно не меняется.
